# FakeKernelSU 开发指南

> 本文档面向二次开发者 / 维护者。面向最终使用者的说明见项目根目录的 `README.md`。

## 一、项目定位

FakeKernelSU 是基于官方 [tiann/KernelSU](https://github.com/tiann/KernelSU) manager 界面的
**纯演示版**：保留全部 UI 与交互，但**不与内核通信、不产生真实 root 权限**，所有"安装 / 授权 / 模块"
都落在 App 自己的私有目录里。

改造的全过程、架构调研、修正点与缺陷清单见 [`改造方案.md`](./改造方案.md)。

## 二、目录结构

```

├── Natives.kt                    # 原 JNI 桥接层 → 纯 Kotlin，数据源换成 FakeState/FakeProfiles
├── fake/                         # ★ 伪装层（全部演示逻辑集中在这里）
│   ├── FakeState.kt              # 单一状态源：安装状态/版本号/机型覆盖/隐藏入口/启动器别名
│   ├── FakeProfiles.kt           # 本地授权表 profiles.json（替代内核 allowlist）
│   ├── FakeModules.kt            # 模块安装/启停/卸载标记，JSON schema 与 ksud 一致
│   └── FakeSu.kt                 # 模拟 su 请求 + ksud 格式 sulog 写入
├── ui/util/
│   ├── KsuCli.kt                 # ksud 桥接 → 本地实现；reboot() 永久 no-op
│   ├── FakeNames.kt              # 启动器别名切换（activity-alias）+ 应用内名称
│   ├── FakeUnlock.kt             # 长按首页/关于页标题解锁控制面板
│   └── SulogHelper.kt            # 日志目录指向 filesDir/adb/ksu/log
├── ui/screen/fakepanel/
│   ├── FakePanelState.kt           # 控制面板共享状态模型（两套皮肤共用）
│   ├── FakeControlPanelMaterial.kt # 控制面板 Material 3 版
│   └── FakeControlPanelMiuix.kt    # 控制面板 Miuix 版
├── ui/screen/superuser/
│   ├── FakeSuRequest.kt            # 共享的"模拟 su 请求"宿主 + Material 授权弹窗
│   └── FakeSuRequestMiuix.kt       # Miuix 版的选应用/授权弹窗
└── ui/screen/install/
    ├── InstallScreen.kt            # 入口：按 UiMode 分发
    ├── InstallMaterial.kt          # Material 3 版
    └── InstallMiuix.kt             # Miuix 版
```

被整体删除的目录（不再需要内核 / native / proto 链路）：
`app/src/main/cpp/`、`magica/`、`aidl/`、`proto/`、`jniLibs/`、`core/tasks/Payload.kt`、
`core/tasks/ExtractImage.kt`。

上游遗留的 `ui/screen/install/InstallUiState.kt`、`InstallUtils.kt`（旧完整安装流程专用）也已删除。

## 二·五、双 UI 约定（新增页面必读）

项目**每个界面都有 Material 与 Miuix 两套实现**，靠 `LocalUiMode` 分发。写新页面时必须遵守：

```kotlin
// 入口文件：只负责按模式分发
when (LocalUiMode.current) {
    UiMode.Miuix -> XxxMiuix(...)
    UiMode.Material -> XxxMaterial(...)
}
```

| 皮肤 | 组件来源 | 注意事项 |
|---|---|---|
| Material | `androidx.compose.material3.*` | |
| Miuix | `top.yukonga.miuix.kmp.basic.*` / `.preference.*` | **不要**在 Miuix 文件里 import material3，否则会露馅 |

Miuix 常用组件对照：

| 需求 | Material | Miuix |
|---|---|---|
| 卡片 | `Card` | `top.yukonga.miuix.kmp.basic.Card` |
| 单选行 | `RadioButton` + `Row` | `RadioButtonPreference(title, selected, onClick, summary)` |
| 开关 | `Switch` | `SwitchPreference(title, summary, checked, onCheckedChange)` |
| 滑块 | `Slider` | `SliderPreference(value, onValueChange, title, valueRange, steps)` |
| 文本输入 | `OutlinedTextField` | 项目自带的 `me.weishu.kernelsu.ui.component.miuix.EditText` |
| 弹窗 | `AlertDialog` | `top.yukonga.miuix.kmp.window.WindowDialog`（内部用 `LocalDismissState.current?.invoke()` 关闭） |
| 顶栏 | `TopAppBar` | `BlurredBar(backdrop) { TopAppBar(...) }` |

坑：

- Miuix 的 `BasicComponent` **没有 `onClick` 参数**，点击要靠 `Modifier.clickable`。
- Miuix 的 `Checkbox` 用 `state = ToggleableState(checked)` + `onClick`，不是 `onCheckedChange`。
- Miuix 组件里的 `stringResource()` 只能在 composable 作用域直接调用；传给非 composable 的
  回调（如 `showConfirm(...)`）前要先取成局部变量。
- Kotlin 属性 `x` 的 setter 与同名方法 `setX(...)` 会产生 **JVM 签名冲突**，变更方法请用
  `updateXxx(...)` 命名。
- Miuix `ButtonDefaults` 只有 `textButtonColors()` 与 `textButtonColorsPrimary()`，**没有** danger 变体。


## 三、构建

### 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| JDK | **21+**（推荐 Android Studio 自带 JBR 25） | AGP 9 不再支持 JDK 17 |
| Gradle | 9.7.1（wrapper 自带） | |
| Android Gradle Plugin | 9.4.1 | |
| Kotlin | 2.4.20 | |
| compileSdk / minSdk | 37 / 31 | |
| build-tools | 36.0.0 | 本机无 37，勿升 |
| NDK / Rust / CMake | **不需要** | native 链路已完全移除 |

### 命令

```bash
export JAVA_HOME="/d/Program Files/Android/Android Studio/jbr"

./gradlew assembleDebug     # app/build/outputs/apk/debug/
./gradlew assembleRelease   # app/build/outputs/apk/release/（R8 + 资源压缩）
```

产物文件名形如 `FakeKernelSU_v3.3.1_327xx-debug.apk`（版本号由 git 生成）。

### 包名 / 名称 / 版本号

均在 `gradle.properties`：

```properties
KSU_PACKAGE_NAME=com.fake.kernelsu
KSU_NAME=FakeKernelSU
```

- **包名**：官方支持 `-PKSU_PACKAGE_NAME` 构建参数。Manifest 中的相对组件名按
  **namespace**（`me.weishu.kernelsu`）解析，`applicationId` 只用于标识 App，因此改包名
  不需要动任何源码路径。
- **版本号**：`getVersionCode()` / `getVersionName()` 直接 exec `git rev-list` / `git describe`，
  **必须在 git 仓库中构建**，否则失败。当前 tag：`v3.3.1`（对齐上游 tiann/KernelSU 最新发布），
  另有历史 tag `v1.1.0` / `v1.0.0-fake` / `v1.0.0`。

## 四、发布签名

release 签名走 **AGP 内置 `signingConfigs`**（`app/build.gradle.kts`），不再依赖
`org.lsposed.lsplugin.apksign`——该插件自 2023-08 停更（最新仍 1.4），内部用
`project.properties` 取签名参数，在 Gradle 9 报 4 条 `Project.getProperties has been deprecated`，
Gradle 10 会直接变成硬错误。

四个键仍是 **Gradle 属性**（`providers.gradleProperty` 读取），在下面任一处配置：

```properties
KEYSTORE_FILE=./my-release.jks   # 相对仓库根目录
KEYSTORE_PASSWORD=xxxx
KEY_ALIAS=my-alias
KEY_PASSWORD=xxxx
```

- 推荐放 `~/.gradle/gradle.properties`（全局、不进仓库）；
- 也可写进项目 `gradle.properties`（注意别提交密钥），或命令行 `-PKEYSTORE_FILE=...` 逐个传；
- `sign.example.properties` 只是给人看的模板，程序不会读取它（也不要再复制成 `sign.properties`，
  插件时代也不读）。

> **未配置密钥库（或文件不存在）时回退到 Android Debug 证书**：`assembleRelease` 照样能出包，
> 但装到别人的手机上无法覆盖正式版。验证方式：
> `apksigner verify --print-certs app/build/outputs/apk/release/*.apk`，
> 看到 `CN=Android Debug` 就是回退态。换正式密钥后必须卸载重装。

## 五、改造要点速查

| 原逻辑 | FakeKernelSU 替代 |
|---|---|
| `Natives` JNI → ioctl `[ksu_driver]` | 纯 Kotlin，读 `FakeState` / `FakeProfiles` |
| `ksud`（Rust `libksud.so`）经 libsu 执行 | `KsuCli` 本地实现，APK 内**无任何自带 .so** |
| `/data/adb/ksu`、`/data/adb/modules` | `filesDir/adb/ksu`、`filesDir/adb/modules` |
| `RootService` / AIDL 枚举包名 | `PackageManager.getInstalledPackages` |
| 官方 `isGKI()` 判定 → 非 GKI 显示"不支持" | 去掉 GKI 条件，非 GKI 设备也显示"未安装" |
| `reboot()` 真实重启 | **永久 no-op**，绝不重启用户手机 |
| `BootCompletedReceiver` / MagicaService | 随 `magica/` 一并删除 |

### 启动器别名机制

Manifest 中注册 4 个 `activity-alias`：`LauncherAliasFake`（默认启用）、`LauncherAliasKsu`、
`LauncherAliasManager`、`LauncherAliasShort`。运行时用
`PackageManager.setComponentEnabledSetting()` 只启用其中一个，实现桌面图标名称切换。

> 坑：相对组件名按 **namespace** 解析，别名必须写成 `me.weishu.kernelsu.LauncherAliasXxx` 全名。

> 坑：在实验室里换过启动器名称后，Android Studio 再点 Run 会报
> `Activity class {com.fake.kernelsu/me.weishu.kernelsu.LauncherAliasFake} does not exist`。
> 原因：AS 从**合并清单**静态解析启动组件，4 个别名里只有 `LauncherAliasFake` 是
> `enabled="true"`，所以它恒定指向这个别名；而 `applyLauncherAlias()` 切到其它名称时会把它
> `setComponentEnabledSetting(DISABLED)`，`KernelSUApplication.onCreate` 又每次冷启动重放持久化
> 选择，于是该组件长期处于禁用态（`adb shell am start -n ...LauncherAliasFake` 同样报 Error type 3）。
> AS 的报错与编译无关，Clean/Rebuild/重装都没用（重装保留 app data）。

> **解法（长期）**：仓库内已带运行配置 `.idea/runConfigurations/app_mainactivity.xml`，
> 在 Run 下拉里选 **app (MainActivity)** 即可（`Specified Activity` =
> `me.weishu.kernelsu.ui.MainActivity`）。alias 只是桌面入口，targetActivity 始终可用，所以怎么换
> 名称都不会再断。若 AS 没自动加载，File → Reload All from Disk 或重启 IDE，也可以手动把现有
> “app” 配置的 Launch Options 改成同样的 Specified Activity。

> **解法（把桌面图标复位成 FakeKernelSU）**：最快是进 app 的实验室把“启动器名称”改回；
> 或用 `run-as` 改持久化值（仅 debug 包）后冷启动一次让 `syncLauncherAlias()` 重设组件：
> `adb exec-out run-as com.fake.kernelsu cat shared_prefs/fake_ksu.xml` 取回、把
> `launcher_alias` 改成 `FAKE` 再写回。
> **注意**：`adb shell pm enable/disable` 在这台设备上会被系统拒绝
> （`SecurityException: Shell cannot change component state`），别指望它。

## 六、编译期踩坑记录

1. `app/build.gradle.kts` 的 `protobuf { }` 块必须整段删除（protobuf 插件已移除）。
2. libsu 6.0.0 的 `Shell.Result` 是抽象类且无公开工厂（没有 `createFromLines`），
   `FlashResult` 只能自己构造。
3. `Natives.Profile.RootProfileFlag` 是**嵌套枚举**：顶层扩展函数要
   `import me.weishu.kernelsu.Natives.Profile.RootProfileFlag`。
4. `Long.toRootProfileFlags()` 必须返回 `List<RootProfileFlag>`（返回 `List<Int>` 会连锁报 5 处类型错误）。
5. `AboutMiuix` 里 `LocalNavigator.current` 不能写在 `rememberFakeUnlockModifier` 的回调里
   （非 composable 上下文），要提到外层。
6. 上游 `gradle.properties` 里的 `android.r8.maxWorkers=4` 已删除：AGP 9.4.1 把它算作
   experimental / 不受支持的工程选项，Android Studio 同步时会以
   `UNSUPPORTED_PROJECT_OPTION_USE` 报出来（中文 IDE 里表现为"项目配置不受支持"）。
   它只影响 release 的 R8 并行度，删掉后 R8 回到默认 1 worker，debug/release 都能正常构建。
   若确实想并行跑 R8，需要同时加 `android.sync.suppressAgpWarnings=UNSUPPORTED_PROJECT_OPTION_USE`
   （会屏蔽整类警告，不是单个选项）。
7. ~~apksign 插件导致的 4 条 `Project.getProperties has been deprecated`~~ **已修复**：插件
   （`org.lsposed.lsplugin.apksign:1.4`，2023-08 后停更）已移除，签名改用 AGP 内置
   `signingConfigs`，Gradle 10 的兼容隐患随之消失。移除前后 release 包证书一致（都是 debug 证书，
   因为一直没配密钥库），无需卸载重装。
8. ~~`Type-safe project accessors is an incubating feature.`~~ **已消除**：当初只是
   `settings.gradle.kts` 里的 `enableFeaturePreview("TYPESAFE_PROJECT_ACCESSORS")` 在自报家门，
   仓库没有用到 `projects.*` 访问器，删掉该行即可。`[Incubating] Problems report` /
   `Build Analyzer` 是 Gradle 9 自带功能，无害，产物在 `build/reports/problems/`（已 gitignore）。

## 七、本机网络坑

GitHub / Gradle 发行包下载在本机会被证书吊销检查阻断（`CRYPT_E_NO_REVOCATION_CHECK`）：

```bash
# Gradle 发行包手动放行
cd ~/.gradle/wrapper/dists/gradle-9.7.1-bin/<hash>/
curl -L --ssl-no-revoke -o gradle-9.7.1-bin.zip \
  https://services.gradle.org/distributions/gradle-9.7.1-bin.zip
```

参考源码可用 `codeload.github.com` 的 tarball 下载（`github.com` 直连不通）。
