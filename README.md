# FakeKernelSU

> 基于官方 [tiann/KernelSU](https://github.com/tiann/KernelSU) 管理器界面改造的 **纯演示版**。
> 它**不修改内核、不产生任何真实 root 权限**，所有"安装/授权/模块"都发生在 App 自己的私有目录里。
> 仅用于演示、教学与二次创作，请勿当作真正的 Root 工具使用。

---

## 一、这个 App 能做什么

| 演示能力 | 说明 |
|---|---|
| 假的"直接安装" | 走一遍 KernelSU 的安装流程，播放高度逼真的 ksud 刷写日志，**但不碰任何分区**，只在 App 内写入一个"已安装"标记 |
| 假的工作状态 | 安装后回到首页，状态卡显示"工作中"，版本号、LKM 模式等全部可自定义 |
| 假的应用授权 | 在「超级用户」页可主动弹出一个高仿的 root 授权对话框，选中"允许 + 记住"后该应用会被标记为 ROOT 授权 |
| 假的模块管理 | 安装模块 ZIP 会真的解压到 App 私有目录，可启用/禁用/卸载（卸载需"重启"生效，与真机一致） |
| 假的 su 日志 | 授权事件按 ksud 的 `sulog` 格式写入本地日志文件，可在 App 内查看 |
| 高度可配置 | 机型、内核版本、指纹、应用名称、启动器名称、版本号、安装状态、root 可用性……全部可调 |

**安全边界**：本 App 永远不会重启你的手机、不会写 `/data/adb`、不会请求任何真实 root。所有数据都在
`Android/data/<包名>/files/adb/` 下，卸载 App 即彻底清除。

## 二、两套 UI，请自选（同一个 APK 内切换）

本项目 **完整保留** KernelSU 的两套界面皮肤，同一个安装包里都包含，可随时切换：

| 皮肤 | 风格 | 适合谁 |
|---|---|---|
| **Material** | 原生 Material 3 动态取色、Expressive 风格 | 喜欢 Google 设计语言、想要现代感 |
| **Miuix** | 类原生 MIUI/HyperOS 的圆润毛玻璃风格 | 喜欢国产 ROM 观感、想要毛玻璃质感 |

**切换方法**：`设置` → `UI 模式` → 选择 `Material` 或 `Miuix`，立即生效并记住。

> 两个皮肤的**功能完全一致**（含控制面板、模拟 su 请求），只是长得不一样。发版时无需用户二选一，
> 装同一个包即可，按喜好在设置里切。

## 三、控制面板（"实验室"）

`设置` → **`FakeKernelSU 实验室`**，可以调整几乎所有演示内容：

- **安装状态**：跟随实际 / 已安装 / 未安装 / 不支持
- **Root 开关**：关闭后首页会显示"已安装，但上方红字提示 root 获取失败"的**混合状态**
- **管理器版本号**、LKM 模式（GKI / LKM / 无）
- **首页信息覆盖**：机型、内核版本、指纹（留空 = 显示真机真实值）
- **应用名称**：启动器名称（4 种预设：`FakeKernelSU` / `KernelSU` / `KSU Manager` / `KSU`）与应用内显示名
- **模拟 su 请求模式**：自选应用 / 随机应用
- **危险区**：重置模拟状态 / 清除全部数据

### 仿真模式（隐藏入口）

打开控制面板里的 **仿真模式** 后：

1. `设置` 里的实验室入口**自动消失**；
2. 改为在 **关于页标题上连点 N 次**（N 可自定义，3~20，默认 7 次）进入控制面板；
3. 连点过程中会提示"再连点 X 次进入实验室"。

适合现场演示、录屏或给别人看，避免被一眼看出是"模拟版"。

## 四、首次使用流程

1. 打开 App → 首页显示 **未安装**（真机如果不是 GKI 内核也照样显示"未安装"，已修掉官方那个"不支持"陷阱）。
2. 点 **安装** → 简易安装页 → 选 **直接安装** → 播放刷写日志 → 提示完成。
3. 返回首页 → 状态卡显示 **工作中**，版本号等均为模拟值。
4. 想体验授权弹窗：切到 **超级用户** 页 → 列表顶部 **模拟 su 请求** → 选择应用 → 允许/拒绝。
   授权结果会出现在该应用的标签上（ROOT 徽标），并写入 su 日志。

## 五、卸载语义

- **临时卸载**：只清掉"已安装"标记，数据（模块、授权、日志）保留。
- **永久卸载**：清标记 + 删掉 App 私有目录下的全部演示数据。

## 六、自行构建

```bash
# 需要 JDK 21+（推荐 Android Studio 自带 JBR）
export JAVA_HOME="/d/Program Files/Android/Android Studio/jbr"

# 包名 / 应用名通过 gradle 参数覆盖，默认见 gradle.properties
./gradlew assembleDebug
# 输出：app/build/outputs/apk/debug/app-debug.apk
```

改包名：编辑 `gradle.properties` 的 `KSU_PACKAGE_NAME`；改显示名：`KSU_NAME`。
（版本号由 `git rev-list`/`git describe` 生成，所以必须在 git 仓库中构建。）

### 发布签名

release 构建由 `org.lsposed.lsplugin.apksign` 插件负责签名。把仓库根目录的
`sign.example.properties` 复制为 `sign.properties` 并填入自己的密钥库即可：

```properties
KEYSTORE_FILE=./my-release.jks
KEYSTORE_PASSWORD=xxxx
KEY_ALIAS=my-alias
KEY_PASSWORD=xxxx
```

> 未配置 `sign.properties` 时插件会回退到 **Android Debug 证书** 签名——可以正常安装测试，
> 但**不要**用它公开发布（用户无法覆盖安装同包名的正式版）。
